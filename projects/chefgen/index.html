Abstract — ChefGen is a lightweight React app that turns a pantry list into a structured, copy‑friendly recipe via an LLM. It prompts for a strict JSON response (no prose) and renders it instantly. It supports OpenAI, Mistral, and Google Gemini providers (plus a local demo) with curated model lists, API key handling, temperature presets, and quick UX touches for speed.

1. Motivation & Constraints

  • Generate useful recipes fast from the ingredients you have.
  • Return a strict JSON object that’s easy to copy/export or re-use elsewhere.
  • Keep the UI minimal and responsive: one page, few controls, instant feedback.

2. UX Goals

  • Type ingredients quickly: Enter or comma to add many; tags are removable.
  • Curated model list per provider with a Custom option for power users.
  • Temperature presets (Speed/Balanced/Quality) mapped to reasonable defaults.
  • Keyboard shortcut Cmd/Ctrl+Enter to generate; copy and download actions.
  • Light/Dark theme toggle, persisted in localStorage.

3. Architecture

The app is a single-page React interface (Vite) that communicates with LLM providers and renders structured output.

4. Prompt & JSON Schema

The system prompt enforces a strict JSON schema to simplify rendering and reuse. The model is asked to output only JSON.

{
  "title": string,
  "servings": number,
  "ready_in_minutes": number,
  "cuisine": string,
  "difficulty": "Easy" | "Intermediate" | "Advanced",
  "ingredients": [{"item": string, "quantity": string, "optional": boolean}],
  "steps": [string, ...],
  "notes": [string, ...],
  "nutrition": {"calories": string, "protein": string, "carbs": string, "fat": string}
}
Why JSON? Copy/paste into notes/apps, export as a file, or feed into other tools without scraping prose.

6. Parsing & Error Handling

ChefGen tolerates fenced blocks and extra text by extracting the first top-level JSON object {...}. It then parses it and renders sections conditionally.

function extractJSON(text){
  if(!text) throw new Error('Empty response');
  const m = text.match(/```(?:json)?\s*([\s\S]*?)\s*```/i);
  const raw = m ? m[1] : text;
  const a = raw.indexOf('{');
  const b = raw.lastIndexOf('}');
  const candidate = (a >= 0 && b > a) ? raw.slice(a, b + 1) : raw;
  return JSON.parse(candidate);
}
Future — Add schema validation (e.g., Zod) and more descriptive provider-specific errors. Consider retries or lower temperature on failure.

7. Security & Correctness

  • Handle API keys securely; prefer limited scope and rotation.
  • Constrain outputs via JSON-only instructions and tuned temperature.
  • Validate response shape before rendering; surface actionable errors to users.

8. Roadmap

  • Server adapters and deployment hardening.
  • Schema validation + “repair JSON” fallback.
  • Shareable permalinks (serialize inputs), Markdown/PDF export.
  • Batch suggestions (multiple recipe variants) and rating loop.
